# Methodology evidence ledger

This ledger records the implementation evidence used by the public methodology section. It is not a performance evaluation.

| Public claim | Authoritative evidence | Qualification |
|---|---|---|
| The site does not train or run a predictive model. | `pyproject.toml` contains data-access and parsing dependencies; `package.json` contains the web runtime; `backend/main.py` uses deterministic mappings, arithmetic, and regular expressions. No training entry point, model artifact, inference client, or model-serving dependency is present. | This describes the current repository only. |
| Search covers listings from the Shanghai, Shenzhen, and Beijing markets. | `stock_master()` requests the SSE main-board and STAR Market lists, the SZSE A-share list, the BSE listed-company list, and two labelled cross-market backup lists. `merge_stock_master_batches()` takes their union, gives official records precedence for duplicate codes, and retains the last cache for an exchange whose official list is unavailable. `/api/coverage` reports exchange counts, source counts, duplicate codes, malformed codes, and the sources reached during the latest refresh. | The union is designed to reduce false omissions, not to certify that every upstream list is current. When an official exchange endpoint is unavailable, coverage remains searchable but that exchange is explicitly not described as officially verified for the refresh. |
| Displayed fields retain provenance. | `field()` rejects values without a `source_id`; every API response includes `sources`, `warnings`, `as_of`, and `status`. | A source link establishes provenance, not substantive correctness. |
| Company modules fail independently. | The frontend requests overview, margin data, contracts, and peers with `Promise.allSettled`; the backend returns module-level warnings instead of fabricating replacements. | A slow upstream can still delay the corresponding module. |
| Contract fields are extracted deterministically. | `extract_contract_fields()` converts announcement PDFs to text and applies explicit regular expressions near counterparty and amount labels. | Unclear or absent fields remain blank; extraction is not semantic document understanding. |
| Cross-company comparison uses a common period. | The frontend intersects available annual periods and selects the latest period present for every compared company. | Companies without a common complete annual period are not compared. |
| The three source modes change collection rules. | `SourceMode` and the mode branches in overview, contracts, capital, and peers distinguish official-first, official-only, and structured-first behavior. | Structured sources are labelled secondary and are not presented as official disclosures. |
| Sector views show recent market snapshots rather than generated classifications. | `/api/sectors` requests current industry or concept-board snapshots from Sina and falls back to Eastmoney; `/api/sectors/{kind}/{board_name}` requests current constituents. Responses use a five-minute cache and retain a secondary `source_id`. | The “technology”, “finance”, “consumption”, “healthcare”, and “energy” controls are disclosed keyword filters over provider board names, not official sector taxonomies. |
| Extended company search is isolated from the default current-listing search. | `/api/search` defaults to `scope=current`; `scope=extended` loads and caches the CNINFO company-code file only when selected, then merges it with the exchange-verified current A-share master. | The extended scope includes historical A-share records and B shares represented in the CNINFO company dictionary. Funds, bonds, pending issuers, and the broader NEEQ universe are not presented as equivalent company reports. |
| Company result icons come from company websites. | The overview obtains the disclosed official website from CNINFO; `/api/company/{code}/logo` resolves the site's declared icon and redirects the image request to that URL. | If the company has no disclosed or reachable site icon, the interface shows an explicit unavailable placeholder rather than a fabricated mark. |
| Company results render progressively. | The frontend starts quote, overview, margin, contract, and peer requests together and writes each settled response into the visible report independently. Quote requests have a 12-second client limit; detailed modules have 30–45-second limits. | Aborting a slow browser request does not imply the upstream service completed; the corresponding module is marked failed instead of delaying every other result. |
| The last report survives navigation within the tab. | Completed and partially completed report state, the active code, selected companies, and source mode are serialized to `sessionStorage` and restored when the home route mounts again. | State is tab-scoped and is not presented as durable research storage. |
| Quote and headline freshness are bounded. | `/api/company/{code}/quote` uses a 30-second cache and retains a Tencent Securities source reference. `/api/market-brief` uses a six-hour cache; the sector page checks every six hours and provides a manual refresh that bypasses the cache. | Both channels are secondary market information. Official-only mode suppresses the secondary quote. |
| Derived financial ratios are arithmetic on disclosed line items, not estimates. | `/api/company/{code}/financials` reads `TOTAL_OPERATE_INCOME`, `OPERATE_COST`, `NETPROFIT`, and `TOTAL_ASSETS` from the structured statements and computes gross margin and return on assets with `ratio()`. Periods without a disclosed operating cost return a null gross margin instead of a substitute. | Ratios use reporting-period values without annualization, so interim ratios are not comparable with annual ones. The response states this. |
| Institutional-holding categories are shown only where the upstream labels them. | `/api/company/{code}/institutions` renders Eastmoney `ORG_TYPE` `00` and `01` as “机构合计” and “基金”; unlabeled type codes are dropped and a warning discloses the omission. | The fund category is confirmed by the fund-level `jjcg` payload carrying `ORG_TYPE` `01`; the remaining codes are not guessed. |
| Private-fund, social-security, QFII, and insurance holdings are read from the upstream holder-type label. | `HOLDER_TYPE_CATEGORIES` maps Eastmoney's own `HOLDER_TYPE` values on the top-ten free-float holder table (`私募基金`, `全国社保基金`, `证券投资基金`, `保险产品`, `QFII`) to the rendered categories; `holder_category()` falls back to a disclosed name keyword only when the upstream leaves the type unclassified. Three report dates are read so the half-year window is covered. | Classification is the upstream's, not an inference from the holder's name. A position that never enters the top ten free-float holders is not disclosed per stock by any public channel, and the response says so. |
| Registration facts come from the company's own exchange, with a link back to that exchange's page. | `/api/company/{code}/exchange` reads the listing record from the exchange that lists the company — `query.sse.com.cn/commonQuery.do` for Shanghai, `szse.cn/api/report/index/companyGeneralization` for Shenzhen, `bse.cn/nqxxController/nqxxCnzq.do` for Beijing — maps it through `EXCHANGE_FIELD_MAP`, and returns deep links to that exchange's company page and announcement page plus the CNINFO company disclosure page built from the `orgId` already present in the filing index. All three link patterns and all three endpoints were verified live before being wired in. | These records are the exchange's own registration data and are tagged official. The exchange pages render client-side, so the link opens the company's entry rather than a static document; periodic reports themselves are served from CNINFO, the CSRC-designated disclosure platform. |
| One announcement crawl serves every module that needs disclosure titles. | `filing_index()` fetches a single five-year CNINFO announcement index per company (12-hour cache) that the contract, sentiment, annual-report, and latest-periodic-report lookups all filter by date; `filing_archive()` fetches the twelve-year index only for the offering-document lookup (30-day cache). `disclosure_records()` holds `CNINFO_QUERY_LOCK`, and `cached()` takes a per-key lock so concurrent modules never issue duplicate or competing paginated crawls. | Before this consolidation three modules paginated the same endpoint concurrently and CNINFO returned non-JSON pages under that load. The five-year window covers the maximum accepted `months` for both the contract and sentiment endpoints. |
| Mandatory filing sections are quoted from the original CNINFO document. | `annual_report_facts()` resolves the latest annual report to its `static.cninfo.com.cn/finalpage` PDF, extracts the text once, and locates the 核心竞争力分析, 公司所处行业情况, 控股股东情况, 实际控制人情况, and 前五名客户/供应商 sections with `report_section()`. `competition_disclosure()` does the same for the 行业竞争 section of the most recent prospectus or offering circular, which is where issuers name their overseas peers. Both cache the extracted text for 30 days and return the document title and filing date. | Sections are reproduced, not summarized; the interface shows the filing date so staleness is visible. A company with no prospectus in the twelve-year window has no competition section, and the response says so rather than assembling a peer list by inference. |
| Filed customer and supplier figures keep their disclosed unit. | `parse_partner_section()` reads the Shenzhen per-counterparty table and the Shanghai/HKEX narrative form, keeps the disclosed `amount_text` with its unit, and converts to yuan through the explicit `AMOUNT_UNITS` table. | Most issuers file anonymized labels such as “客户1”; the module detects the all-anonymous case and states that no counterparty names were disclosed. Where only a total is filed, the per-counterparty list stays empty. |
| Negative-sentiment rows are title keyword matches over disclosed documents. | `/api/company/{code}/sentiment` applies `NEGATIVE_WORDS` to CNINFO announcement titles over twelve months and to Eastmoney per-stock news titles, returning the matched words per row along with the full keyword table. | The module performs no semantic judgement of fault, materiality, or outcome; a keyword hit is a pointer to the original document. |
| Money-flow caliber is named rather than normalized. | `/api/company/{code}/moneyflow` returns `caliber`; the Eastmoney path reports the 主力（超大单＋大单）caliber and the Sina fallback path reports the all-order net-inflow caliber, with an explicit warning when the fallback is used. | The two providers measure different things. The interface prints the caliber actually used instead of merging them into one series. |
| Controller information comes from the filing, with a secondary structured cross-check. | The annual report's 控股股东情况 and 实际控制人情况 sections carry the mandatory disclosure — for an enterprise controller the name, legal representative, incorporation date, and 主要经营业务; for a natural person the nationality, residency status, and 主要职业及职务. `ths_control_chain()` and Eastmoney's `sjkzr` record are rendered separately as a structured cross-check. | The listed company's filings do not disclose an enterprise controller's own net profit. What the filing states is shown; nothing further is inferred. |
| The segment table reports shares and margins as percentages. | Eastmoney returns 收入比例 and 毛利率 as decimal fractions; `business_segments()` multiplies both by 100 through `number_or_none` so the field names `revenue_share_percent` and `gross_margin_percent` match the values. | Verified against the same company's computed gross margin in `/financials`, which is derived independently from the income statement. |
| “今日排位” keeps metric comparisons independent. | The selected board's full constituent response is sorted separately for daily change, turnover amount, turnover rate, market capitalization, and positive low price/earnings ratio. Each metric keeps its own top ten and scale; adding a metric mounts a new chart and a new pair of table columns. | Rankings are snapshots of secondary provider data, not screening recommendations. Negative or missing P/E values are excluded only from the low-P/E ranking. |

## Implementation change recorded on 2026-07-30

- The code-table refresh now requests all official and backup lists independently and merges every successful response instead of stopping after the first backup.
- Duplicate codes retain the official exchange record. If an official exchange list fails, codes from the last cache for that exchange remain available.
- Expired code-table caches are served immediately while refresh runs in the background; an upstream timeout no longer blocks an ordinary search.
- `/api/coverage` exposes the current exchange counts and integrity checks. A missing official source produces an explicit partial-verification warning.

Detailed timings and channel qualifications are recorded in `docs/source_coverage_audit_2026-07-30.md`.
